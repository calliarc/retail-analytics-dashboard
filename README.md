# Retail Analytics Dashboard

Retail analytics pipeline and dashboard with sample data.

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![CI](https://github.com/calliarc/retail-analytics-dashboard/actions/workflows/ci.yml/badge.svg)](https://github.com/calliarc/retail-analytics-dashboard/actions/workflows/ci.yml)
![Status: v0.1.0](https://img.shields.io/badge/status-v0.1.0-green)

> **Status:** v0.1.0, first working release. Synthetic data generator, dbt models on DuckDB,
> and a Streamlit dashboard all run locally. Star or watch the repo to follow progress.

> **All data in this project is synthetic.** It is generated by `data_gen/` and does not
> describe any real business, store, product or person.

## Features

- Synthetic sample data: stores, products, sales, inventory and customers
- dbt models for sales, margin, basket and inventory metrics
- Dashboard for sales trends, top products, stockouts and store comparison
- Customer cohort and repeat-purchase analysis
- Runs locally with no cloud account required

## Tech stack

- Python (3.10+), pandas, NumPy
- DuckDB
- dbt (dbt-core + dbt-duckdb)
- Streamlit + Plotly
- Power BI (optional): connection guide in [docs/powerbi.md](docs/powerbi.md). A `.pbit` template is not included yet.

## Getting started

Requirements: Python 3.10 or newer, `make`, about 200 MB of disk for the virtual environment.

```bash
git clone https://github.com/calliarc/retail-analytics-dashboard.git
cd retail-analytics-dashboard
make all      # creates .venv, installs requirements, generates data, runs dbt build
make app      # opens the dashboard at http://localhost:8501
```

`make all` takes a few minutes, mostly installing dependencies; generating data and running dbt take under 30 seconds. The default dataset covers 2 years, 8 stores, 120 products and
12,000 loyalty members (about 245k orders and 725k order lines). Add `PRESET=small` for a tiny
dataset (3 stores, 90 days) that builds in seconds.

| Command        | What it does                                                                 |
|----------------|------------------------------------------------------------------------------|
| `make setup`   | Create `.venv` and install `requirements.txt`                                |
| `make data`    | Generate synthetic Parquet files into `data/raw/` (`PRESET=`, `SEED=`)       |
| `make build`   | `dbt build`: run all models and tests into `data/retail.duckdb`              |
| `make app`     | Launch the Streamlit dashboard                                               |
| `make test`    | Run pytest (generator tests + end-to-end dbt/app smoke test)                 |
| `make export`  | Export marts to `data/exports/*.parquet` (for Power BI or other tools)       |
| `make docs`    | Generate and serve dbt docs (lineage graph)                                  |
| `make clean`   | Remove generated data and dbt artifacts                                      |

Use `make <target> VENV=` to run with the currently active Python instead of `.venv`.

### Without make

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m data_gen --out data/raw                         # --preset small --seed 7 --format csv ...
dbt build --project-dir dbt --profiles-dir dbt            # run from the repo root
streamlit run app/streamlit_app.py
```

Environment variables (all optional): `RAW_DATA_DIR` (default `data/raw`), `RAW_FORMAT`
(`parquet` or `csv`), `DUCKDB_PATH` (default `data/retail.duckdb`). Relative paths are resolved
from the directory you run dbt from, so run it from the repo root.

## Dashboard

The Streamlit app (`app/`) reads the dbt marts from DuckDB in read-only mode. Global sidebar
filters for **date range, store and category** apply across pages.

| Page             | Shows                                                                                   |
|------------------|-----------------------------------------------------------------------------------------|
| Overview         | Net revenue, orders, AOV, gross margin, units, stockout rate vs previous period; weekly trend; category mix |
| Sales trends     | Daily/weekly/monthly trends split by category, store, region or format; weekday profile; promo share |
| Top products     | Top N products by net revenue, units or gross margin                                    |
| Stockouts        | Stockout rate over time, most stocked-out store x product, items under 3 days of cover  |
| Store comparison | Revenue, revenue per day and per sq ft, AOV, margin, member share, stockout rate        |
| Cohorts          | Monthly acquisition cohort heatmap (retention or cumulative repeat rate)                |
| Basket & margin  | Product pairs by lift / attach rate; margin and discount rate by category               |

## Data model

```
data_gen (Python, seeded)  ->  data/raw/*.parquet  ->  dbt (DuckDB)  ->  data/retail.duckdb  ->  Streamlit / Power BI
                                                    staging (views) -> marts (tables)
```

**Raw tables** (`data/raw/`, written by `python -m data_gen`): `stores`, `products`, `customers`,
`promotions`, `orders`, `order_lines`, `inventory_snapshots`, plus `_manifest.json` with the config
and row counts. The generator is deterministic for a given seed and includes annual seasonality
(summer bump, Black Friday spike, December peak), weekday effects, growth, category promotions,
basket affinity between complementary products, a store that opens mid-period, and a daily
replenishment simulation (reorder points, lead times, supplier delays) so stockouts occur and
suppress sales. Guest orders have no `customer_id`; loyalty members have no names or contact details.

**Staging** (`dbt/models/staging`, schema `staging`): one typed view per raw table (`stg_*`).

**Marts** (`dbt/models/marts`, schema `main`):

| Model              | Grain                              | Key columns / metrics                                                    |
|--------------------|------------------------------------|--------------------------------------------------------------------------|
| `fct_sales`        | order line                         | quantity, gross/net revenue, discount, COGS, gross margin, promo flag    |
| `dim_date`         | day                                | week/month start, year, quarter, weekday, weekend flag                   |
| `dim_store`        | store                              | region, format, square feet, open date                                   |
| `dim_product`      | product                            | category, brand, unit cost/price, list margin, price band                |
| `dim_customer`     | loyalty member                     | tier, age band, home store, first/last order, cohort month, lifetime value |
| `mart_daily_sales` | date x store x category            | orders, units, gross/net revenue, discount, COGS, margin, promo revenue   |
| `mart_margin`      | month x store x product            | revenue, COGS, gross margin %, discount rate, promo revenue share        |
| `mart_basket`      | product pair (A < B)               | pair orders, support, attach rate A->B and B->A, lift                    |
| `mart_inventory`   | date x store x product             | on hand, on order, received, sold, stockout flag, trailing avg sales, days of cover |
| `mart_cohorts`     | cohort month x months since first  | cohort size, active customers, retention rate, cumulative repeat rate    |

**Tests:** 93 dbt tests (`unique`, `not_null`, `relationships`, `accepted_values` and singular
tests for revenue math, mart reconciliation, basket ratios, non-negative inventory and cohort
consistency) run as part of `make build`. `pytest` covers generator determinism, integrity,
stock conservation and seasonality, and runs an end-to-end smoke test that builds the small
dataset with dbt, checks mart row counts and renders every dashboard page.
